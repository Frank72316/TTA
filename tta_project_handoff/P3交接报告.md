# TTA P3 实验交接报告

P3 已完成固定增强幅度下的推理预算测量、幅度对照、留出策略评估和米制深度复验。本轮最直接的结论是，增加评分次数明显提高了延迟，而开发集上的少量准确率增益没有在新提示词上复现。现有原始评分、计时和深度误差矩足以在 CPU 上复算结果。[P3 实验报告](../P3/report.md) · [预算曲线](../P3/results/budget_curves.png)

## 工作基础和本轮交付

P1 建立了 ImageRewardDB 的人工排序口径，并区分了候选共同涨落与实际分差。P2 在固定三次预算下测得平移既能纠正错例，也会改错。原始分差较小的图对更容易改判。P3 复用 P2 冻结的 256 对图作为开发集，另冻结 88 对未在 P1、P2 使用过的提示词作为留出集。四档预算均使用同一台 NVIDIA L4 重新测得的 HPS v2.1 评分，采用同一个八方向平移池。旧 RTX 4080 SUPER 数据只用于相同视图的对账。[P1 重配对照](../P1/pairing/report.md) · [P2 独立复验](../P2/translation/report.md) · [P3 冻结协议](../P3/protocol.md)

| 交付 | 主要结果 |
|---|---|
| 预算与成本 | 在 256 对开发图上，每图 1、2、4、8 次的严格选对率为 68.36%、68.60%、68.88%、68.99%，每对延迟中位数为 165、263、457、837 ms。4→8 次多出约 380 ms，点估计增加 0.112 个百分点，95% 配对区间为 [−0.677, +0.830]。 |
| 幅度与留出策略 | 固定每图四次时，1.5%、3%、6% 平移的选对率差异仍不确定。HPS 在留出集的 8 次预算比原图低 1.136 个百分点，CLIP 复验也没有测得明确净收益。低分差触发规则在同平均预算下未显示明确优势。 |
| 误差分解与连续真值 | 偏好任务使用校准胜率残差衡量视角误差相关性。NYU Depth V2 复验用 32 帧拟合、32 帧留出。米制误差的视角间相关约为 0.976，8 次预算的留出 MSE 点估计比原图低 1.10%，三个相邻预算的配对区间均跨零。 |

## 如何复查

1. 从实验报告定位主结果。每图预算包括原图，图对的两张候选各消耗同样次数。准确率先在各方向子集判定，再等权汇总。耗时是每对图的实测累计墙钟时间。同分保留在严格选对率分母里。[实验报告](../P3/report.md)
2. 对照开发集和留出集的逐图结果、原始评分、计时与环境校验和。留出图对和实验环境均有冻结记录或输入哈希。深度误差矩可复算本轮全部预算的 MSE 和分区误差。[开发集预算](../P3/results/development-3/budget_summary.csv) · [留出集清单](../P3/results/holdout/pairs.csv) · [运行环境](../P3/results/development-3/environment.json) · [深度误差矩](../P3/results/depth/depth_moments.json)
3. 从仓库根目录按 P3 README 的 CPU 命令重建预算表、留出策略表、深度曲线和图。归档包含 18,368 条单图偏好评分与 64 帧的深度误差统计。实验实例已关闭并删除，复查无需重新启动 GPU。[CPU 复算命令](../P3/README.md#从归档结果复算)

## 接手时的判断

在这批图对、两种评分器和当前平移条件下，保留原图一次评分作为默认基线。用留出集评价新的触发条件时，沿用相同平均预算、配对区间和纠正／改错口径。ImageRewardDB 的标签只给出人工赢家，偏好任务的偏差分析应按二元概率代理解释。需要测连续偏差时，沿用米制真值和共同可见区。

P3 的预算结论可作为后续实验的成本参考。P4 继续检验聚合空间与任务变换律，需要在同一预测和坐标对齐条件下比较不同聚合空间。[P3 与 P4 研究方案](../doc/TTA%20idea.md)
